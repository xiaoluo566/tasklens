# TaskLens 需求规格与验收矩阵

> 这是单 Agent 版本的开发规格与验收矩阵。P0 代码和自动化契约已落地；真实 Chrome/CDP、Docker 和窄屏 E2E 仍需在目标环境完成，量化指标必须以实际测试报告为准。

## 1. 优先级定义

- **P0**：没有它就无法证明项目主价值；首个可运行切片必须包含。
- **P1**：增强深度和可用性，P0 稳定后实现。
- **P2**：候选扩展，不进入九天首轮承诺。

## 6. 测试契约

实现阶段必须遵循 RED → GREEN → REFACTOR：

1. 单元测试：Runtime 状态机、断言、脱敏、边界、汇总和 SQLite 事务失败；
2. 集成测试：HTTP 首页、task、health、summary、runs、detail、400/404；
3. CLI 测试：任务参数、端口错误、Dashboard 不记录自身；
4. E2E 冒烟：真实浏览器执行单 Agent 任务、筛选失败运行、打开详情和回放；
5. 覆盖率：新增模块和关键分支至少 80%。

## 7. Definition of Done

代码层 P0 已具备自动化证据；要把项目标记为“可发布交付”，还需要完成以下环境验收：

- 所有 P0 需求有通过的自动化测试；（已完成）
- 全量上游测试通过，或对既有环境失败给出可复现说明；（当前 257 通过，1 个既有 Windows checkout 资源链接失败，详见交付记录）
- 真实浏览器验证桌面和窄屏页面；
- 安全审查确认没有硬编码密钥和未脱敏任务字段；
- README、架构决策和运行方式同步更新；
- Git diff 仅包含本项目范围内的改动。
