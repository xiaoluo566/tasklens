# TaskLens 需求规格与验收矩阵

> 这是开发前规格。状态栏中的“待实现”是当前真实状态，不能在简历中写成已交付指标。

## 1. 优先级定义

- **P0**：没有它就无法证明项目主价值；首个可运行切片必须包含。
- **P1**：增强深度和可用性，P0 稳定后实现。
- **P2**：候选扩展，不进入九天首轮承诺。

## 6. 测试契约

实现阶段必须遵循 RED → GREEN → REFACTOR：

1. 单元测试：脱敏、边界、汇总、坏行和存储失败；
2. 集成测试：HTTP 首页、health、summary、runs、detail、400/404；
3. CLI 测试：参数解析、端口错误、Dashboard 不记录自身；
4. E2E 冒烟：真实浏览器加载页面、筛选失败运行、打开详情；
5. 覆盖率：新增模块和关键分支至少 80%。

## 7. Definition of Done

只有同时满足以下条件，才可以把 P0 标记为完成：

- 所有 P0 需求有通过的自动化测试；
- 全量上游测试通过，或对既有环境失败给出可复现说明；
- 真实浏览器验证桌面和窄屏页面；
- 安全审查确认没有硬编码密钥和未脱敏任务字段；
- README、架构决策和运行方式同步更新；
- Git diff 仅包含本项目范围内的改动。
