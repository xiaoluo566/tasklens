# TaskLens PRD：单 Agent AI 浏览器测试与运行观测台

> 文档状态：Draft / 开发前评审稿。本文档描述要做什么，不描述已经做完什么。

## 1. Executive Summary

我们计划为 `browser-harness` 增加一个名为 TaskLens 的单 Agent 浏览器测试与运行观测台，面向测试开发和 Agent 开发者，解决浏览器自动化任务“结果难验证、失败难定位、耗时难比较、证据难沉淀”的问题。首版将通过单 Agent Runtime、断言、SQLite 运行记录、FastAPI 和响应式 Dashboard 展示任务摘要、成功率、失败步骤、helper 耗时和浏览器类型，同时对敏感信息做本地脱敏；目标是在不改变上游浏览器控制语义的前提下，让一次任务可以被验证、复盘和回归。

## 2. Problem Statement

### 谁遇到问题

- 使用单 Agent 驱动真实浏览器的测试开发同学；
- 调试浏览器 Agent、需要反复重跑任务的开发者；
- 在本地或云服务器执行短周期回归任务的个人开发者。

### 具体问题

上游 Harness 已经有 helper trace、录制和匿名 telemetry 等能力，但缺少一个面向开发者的本地运行历史视图，也没有把 helper 成功与业务结果断言统一起来。终端输出是短暂的，录制偏向过程回放，匿名 telemetry 不适合作为个人任务的可检索证据。因此开发者需要手动复制日志、猜测失败步骤、比较多次运行的耗时。

### 用户影响

- 失败复盘耗时增加，定位依赖人工翻终端；
- 性能回归缺少同一口径的历史数据；
- Agent 生成的 helper 质量无法通过运行证据持续观察。

### 现阶段证据边界

本项目是个人项目，不把未测量的市场规模或线上用户数据写成事实。上述问题来自对开源依赖 CLI 结构和典型测试开发工作流的工程判断；开发阶段需要用真实任务样本验证字段和页面是否足够。

## 3. Target Users & Jobs-to-be-Done

### 主要用户：测试开发实习生

- 目标：快速确认自动化任务是否稳定，定位失败原因；
- 痛点：工具链多、日志分散、需要把结果写进缺陷或周报；
- 使用频率：每天多次运行，单次任务几十秒到数分钟。

### 次要用户：Agent/Harness 开发者

- 目标：观察 helper 是否复用、哪些步骤变慢、不同浏览器后端是否有差异；
- 痛点：只看最终成功/失败无法解释中间过程。

## 4. Strategic Context：为什么现在做

这个项目适合作为测开/AI 测试方向的个人项目，因为它同时覆盖：

- Python CLI、单 Agent Runtime 和进程生命周期；
- 浏览器自动化执行链路；
- 测试数据建模、脱敏和失败语义；
- FastAPI、前端页面和端到端验证；
- 在成熟开源项目上的增量设计，而不是从零搭空壳 Demo。

本阶段只冻结设计，不把“市场需求”“性能提升”“覆盖率”等目标写成已实现成果。

## 5. Solution Overview

### 核心方案

在 `run.py` 的脚本执行生命周期接入单 Agent Runtime，并生成一条 bounded run record，写入本地 SQLite；Dashboard 通过 FastAPI 读取记录并展示：

1. 运行总览：总次数、成功/失败、成功率、平均耗时；
2. 运行列表：按状态、浏览器和数量过滤；
3. 运行详情：任务摘要、退出码、错误摘要、helper 步骤；
4. 性能视图：单次运行的 helper 耗时排序和浏览器分布；
5. 安全边界：URL 查询参数、token、password、cookie、Authorization 等字段脱敏。

### 用户流程

```text
提交自然语言目标和 TaskSpec
  -> 单 Agent 观察页面、选择动作并执行 helper
  -> 断言校验结果，必要时进行有界重试
  -> 生成脱敏运行记录并写入 SQLite
  -> 启动 dashboard
  -> 查看 summary / 过滤 runs / 打开详情
  -> 根据失败步骤或慢 helper 修改任务
```

## 6. Success Metrics

### 产品指标（开发验收目标）

| 指标 | 目标 |
| --- | --- |
| 失败任务定位路径 | 3 次点击内看到失败步骤和错误摘要 |
| 首屏可用时间 | 本地服务启动后 2 秒内出现空状态或运行列表 |
| 记录安全性 | 测试样本中的敏感字段不出现在 JSONL、API 和页面 |
| 兼容性 | 观测旁路异常不改变原脚本退出码 |

### 工程指标

- 新增 Python 模块单元/API 测试覆盖率不低于 80%；
- 现有开源基线测试不因 TaskLens 功能产生回归；
- 页面在桌面端和 375px 窄屏下均可读；
- 模型调用通过可替换 Provider 接口隔离；测试模式使用确定性 Fake Provider，不依赖外部网络。

## 7. User Stories & Acceptance Criteria

### Story 1：查看最近运行

作为测试开发，我希望看到最近的运行列表，以便快速选择需要复盘的任务。

验收：

- [ ] 列表显示状态、任务摘要、浏览器、耗时和时间；
- [ ] 默认按最近完成时间倒序；
- [ ] 没有记录时显示明确空状态；
- [ ] 单次返回数量有上限。

### Story 2：定位失败步骤

作为测试开发，我希望打开一次失败运行并看到失败 helper，以便缩短定位时间。

验收：

- [ ] 详情包含退出码、错误摘要和步骤序列；
- [ ] 失败步骤有明确状态标识；
- [ ] 页面不展示未经脱敏的敏感参数；
- [ ] 不存在的运行 ID 返回结构化 404。

### Story 3：比较耗时

作为 Harness 开发者，我希望看到 helper 耗时排序，以便发现回归瓶颈。

验收：

- [ ] 每个步骤包含耗时字段；
- [ ] 详情可以按耗时降序展示；
- [ ] 缺少耗时或损坏记录不会导致页面崩溃。

### Story 4：安全降级

作为使用者，我希望观测功能出错时任务仍按原逻辑结束，以便不会因为辅助功能阻断生产脚本。

验收：

- [ ] 目录不可写时脚本仍返回原退出码；
- [ ] SQLite 查询或事务失败时主任务仍返回原结果，health 标记存储异常；
- [ ] 端口占用时只报告 Dashboard 启动错误，不修改运行记录。

## 8. Out of Scope

- 云端多租户、账号、权限和远程共享；
- 云端数据库、消息队列和长期指标告警；
- 自动根因分析和自动修复；模型调用通过可替换 Provider 接口接入，但不在本轮实现多 Agent 协作；
- 重新实现 CDP、浏览器连接或录制能力；
- 大型图表库、设计系统和移动原生客户端；
- 把个人任务原文、Cookie 或完整页面内容上传第三方服务。

## 9. Dependencies & Risks

| 风险/依赖 | 影响 | 缓解方案 |
| --- | --- | --- |
| `run.py` 生命周期分支多 | 可能漏记失败路径 | 先写成功、SystemExit、异常三类测试 |
| 任务内容含敏感信息 | 本地记录泄露 | 字段级脱敏、长度上限、默认回环监听 |
| SQLite 长期增长 | 磁盘占用 | 记录上限、索引和清理命令设计 |
| 开源依赖持续变更 | 项目难以跟进 | 保持小模块、记录依赖基线和同步策略 |
| 页面数据不完整 | 指标误导 | 显示空值/未知状态，不猜测缺失数据 |
